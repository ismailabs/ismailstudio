# Supporting experience details

## Project studies

All four must open a usable pop-up/dialog on user request where JavaScript is enabled, with a permanent shareable or crawlable URL if the current working architecture supports it. Each: title, **Concept Project** disclosure, short imagined/design intent/problem (explicitly framed as a self-initiated concept), concise design solution, authentic current live preview and outbound live demo link. No fabricated interview/client/metric. Keep dialogs keyboard navigable and Escape closable with focus restored.

Project previews must remain identifiable as existing work, including their internal design colors (even if their screenshots contain orange)—the site's own **new brand accents** must not use orange. Do not recolor authentic screenshots to match V3 palette.

## Contact

Retain current Name (required), Business name (optional), Email (required), Package, Target timeline (optional), Project description (required). Step 1 identity; Step 2 project details; Step 3 review and send. Keep provider payload field names; test native POST, honeypot, error summaries, focus invalid field, no duplicate send, timeouts and retries. No invented phone field or 24-hour response promise. After a user selects Starter/Business/Premium, preserve package selection through the contact flow.

## FAQ — concise 5–7 questions

- What do the three packages include and exclude?
- What does Basic/Technical/Advanced one-time SEO actually cover?
- How do price and revisions work?
- Will I own the site and domain after delivery? (Answer only from verified contract/ownership terms.)
- How long does a project usually take? (Avoid fabricated deadline.)
- What happens when I need changes after launch? (Maintenance separately agreed.)
- Can you build shops/bookings/backend systems? (Current packages are frontend-focused.)

Use actual current terms, legal eligibility and provider arrangements; don't improvise contractual promises.
